## Core Patterns

### 1. Database Access & Row-Level Security (RLS)

**Principle:** All data access is controlled at the Postgres layer, not the UI.

```typescript
// lib/db/queries.ts - Reusable query patterns

// Example: Get submissions visible to current user (enforced by RLS)
export async function getMySubmissions(userId: string, client: SupabaseClient) {
  const { data, error } = await client
    .from("submissions")
    .select("*")
    .eq("user_id", userId);
  
  if (error) throw new Error(`Failed to fetch submissions: ${error.message}`);
  return data;
}

// Example: Staff can see all submissions in their district (RLS enforces this)
export async function getDistrictSubmissions(districtId: string, client: SupabaseClient) {
  const { data, error } = await client
    .from("submissions")
    .select("*")
    .eq("district_id", districtId);
  
  if (error) throw new Error(`Failed to fetch district submissions: ${error.message}`);
  return data;
}
```

**RLS Policies (SQL):**
```sql
-- Citizens can only see their own submissions
CREATE POLICY "citizens_own_submissions" ON submissions
  FOR SELECT USING (
    auth.uid() = user_id OR
    (SELECT role FROM profiles WHERE id = auth.uid()) = 'staff'
  );

-- Staff can see all submissions in their district
CREATE POLICY "staff_district_submissions" ON submissions
  FOR SELECT USING (
    (SELECT role FROM profiles WHERE id = auth.uid()) = 'staff' AND
    (SELECT district_id FROM profiles WHERE id = auth.uid()) = submissions.district_id
  );
```

**Why:** RLS is enforced at the database layer; no amount of clever UI can bypass it. This is fast to audit and secure by default.

```typescript

export function createClient() {

```

**Server Component auth:**

```typescript
// app/dashboard/page.tsx (server component)
import { createServerComponentClient } from "@supabase/ssr";
import { redirect } from "next/navigation";

export default async function DashboardPage() {
  const supabase = createServerComponentClient();
  
  const { data: { user } } = await supabase.auth.getUser();
  if (!user) redirect("/auth/login");
  
  const { data: profile } = await supabase
    .from("profiles")
    .select("role, district_id")
    .eq("id", user.id)
    .single();

  if (!profile) redirect("/auth/onboarding");

  return <DashboardLayout role={profile.role} districtId={profile.district_id} />;
}
```

**Route handler (API):**

```typescript
// app/api/submissions/route.ts
import { createRouteHandlerClient } from "@supabase/ssr";
import { cookies } from "next/headers";

export async function POST(request: Request) {
  const supabase = createRouteHandlerClient({ cookies });
  
  const { data: { user } } = await supabase.auth.getUser();
  if (!user) return Response.json({ error: "Unauthorized" }, { status: 401 });

  const body = await request.json();
  
  // RLS will enforce: user can only insert with their own user_id
  const { data, error } = await supabase
    .from("submissions")
    .insert([{ ...body, user_id: user.id }])
    .select();

  if (error) return Response.json({ error: error.message }, { status: 400 });
  return Response.json(data);
}
```

**Middleware (auth guards):**

```typescript
// middleware.ts
import { createMiddlewareClient } from "@supabase/ssr";
import { NextRequest, NextResponse } from "next/server";

export async function middleware(request: NextRequest) {
  const response = NextResponse.next();
  const supabase = createMiddlewareClient({ req: request, res: response });

  const { data: { session } } = await supabase.auth.getSession();

  // Redirect to login if accessing protected routes
  if (!session && request.nextUrl.pathname.startsWith("/dashboard")) {
    return NextResponse.redirect(new URL("/auth/login", request.url));
  }

  return response;
}

export const config = {
  matcher: ["/dashboard/:path*", "/api/protected/:path*"],
};
```

### 3. Form Handling & Validation

**Use shadcn/ui + React Hook Form + Zod:**

```typescript
// components/forms/SubmitIssueForm.tsx
"use client";

import { useRouter } from "next/navigation";
import { useForm } from "react-hook-form";
import { zodResolver } from "@hookform/resolvers/zod";
import { z } from "zod";
import { Button } from "@/components/ui/button";
import { Input } from "@/components/ui/input";
import { Textarea } from "@/components/ui/textarea";

const schema = z.object({
  title: z.string().min(3, "Title must be at least 3 chars"),
  description: z.string().min(10, "Description must be at least 10 chars"),
  latitude: z.number().min(-90).max(90),
  longitude: z.number().min(-180).max(180),
});

type FormData = z.infer<typeof schema>;

export function SubmitIssueForm() {
  const router = useRouter();
  const { register, handleSubmit, formState: { errors, isSubmitting } } = useForm<FormData>({
    resolver: zodResolver(schema),
  });

  async function onSubmit(data: FormData) {
    const res = await fetch("/api/submissions", {
      method: "POST",
      body: JSON.stringify(data),
    });

    if (!res.ok) {
      const error = await res.json();
      alert(`Error: ${error.error}`);
      return;
    }

    router.refresh();
    alert("Issue submitted!");
  }

  return (
    <form onSubmit={handleSubmit(onSubmit)} className="space-y-4">
      <div>
        <Input {...register("title")} placeholder="Issue title" />
        {errors.title && <span className="text-red-500 text-sm">{errors.title.message}</span>}
      </div>
      <div>
        <Textarea {...register("description")} placeholder="Describe the issue" />
        {errors.description && <span className="text-red-500 text-sm">{errors.description.message}</span>}
      </div>
      <Button type="submit" disabled={isSubmitting}>
        {isSubmitting ? "Submitting..." : "Submit"}
      </Button>
    </form>
  );
}
```

**Why:** Zod + React Hook Form keep validation DRY and co-located with the form. No separate validation logic.

### 6. TypeScript & Type Safety

**Always use types from Supabase:**


**In components & functions:**

```typescript
// components/dashboard/SubmissionList.tsx
import { Submission } from "@/lib/db/types";

interface SubmissionListProps {
  submissions: Submission[];
  onRefresh: () => Promise<void>;
}

export function SubmissionList({ submissions, onRefresh }: SubmissionListProps) {

    <div>
      {submissions.map((sub) => (
```

**Why:** Type safety catches errors at build time, not runtime. It's especially important in a multi-developer environment where one person's mistake doesn't break another's code.

### 7. Supabase Client Usage

**Always use the right client:**

| Context | Client | Example |
|---------|--------|---------|
| Browser (client component) | `createBrowserClient` | `useEffect` hooks, click handlers |
| Server Component | `createServerComponentClient` | Direct `await` calls in component body |
| Route Handler | `createRouteHandlerClient` | POST/GET/PUT requests |
| Server Action | `createServerActionClient` | Form actions, mutations |
| Admin operations (server-only) | `createServiceRoleClient` | Cron jobs, migrations |

**Never use cookies or auth in browser client-side operations directly for sensitive data.**

### 8. Error Handling

**Pattern: Fail loudly in development, gracefully in production.**

```typescript
// Route handler example
export async function POST(request: Request) {
  try {
    const supabase = createRouteHandlerClient({ cookies });
    const { data: { user } } = await supabase.auth.getUser();
    
    if (!user) {
      return Response.json({ error: "Unauthorized" }, { status: 401 });
    }

    const body = await request.json();
    const { data, error } = await supabase.from("submissions").insert([body]).select();

    if (error) {
      console.error("Insert error:", error);
      return Response.json(
        { error: "Failed to create submission" }, 
        { status: 400 }
      );
    }

    return Response.json(data);
  } catch (err) {
    console.error("Unexpected error in POST /api/submissions:", err);
    return Response.json(
      { error: "Internal server error" }, 
      { status: 500 }
    );
  }
}
```

**Client-side (in forms):**

```typescript
async function onSubmit(data: FormData) {
  try {
    const res = await fetch("/api/submissions", {
      method: "POST",
      body: JSON.stringify(data),
    });

    if (!res.ok) {
      const error = await res.json();
      throw new Error(error.error || "Request failed");
    }

    const result = await res.json();
    console.log("Success:", result);
    router.refresh();
  } catch (err) {
    const message = err instanceof Error ? err.message : "Unknown error";
    setError(message);
    console.error("Form submission error:", message);
  }
}
```

**Detect online/offline:**

```typescript
// lib/hooks.ts
export function useOnlineStatus() {
  const [isOnline, setIsOnline] = useState(true);

  useEffect(() => {
    const handleOnline = () => setIsOnline(true);
    const handleOffline = () => setIsOnline(false);

    window.addEventListener("online", handleOnline);
    window.addEventListener("offline", handleOffline);

    return () => {
      window.removeEventListener("online", handleOnline);
      window.removeEventListener("offline", handleOffline);
    };
  }, []);

  return isOnline;
}
```

### 10. Styling

**Use Tailwind CSS + shadcn/ui. Avoid inline styles.**

```typescript

<div className="flex items-center gap-4 p-4 bg-gray-50 rounded-lg">
  <Button variant="outline" size="sm">Cancel</Button>
  <Button variant="default" size="sm">Save</Button>

<div style={{ display: "flex", gap: "1rem", padding: "1rem" }}>
```

## Common Tasks for AI Agents

### Add a New Form
1. Create schema in `lib/db/types.ts`.
2. Create Zod validation schema in the component or `lib/validation.ts`.
3. Build form component in `components/forms/`.
4. Connect to route handler in `app/api/`.
5. Test with different user roles (RLS will prevent unauthorized access).

### Add a New Dashboard View
1. Create component in `components/dashboard/`.
2. Fetch data in a server component (not client), using `createServerComponentClient`.
3. Pass data to client sub-components as props.
4. Use Tailwind + shadcn/ui for layout.

### Add a Database Migration
1. Create `supabase/migrations/v00X_description.sql` with exact SQL.
2. Write clear comments explaining schema changes.
3. Test locally: run migration, verify RLS policies, test with different roles.
4. Update `lib/db/types.ts` to reflect new tables/columns.

### Modify RLS Policies
1. Edit policies in Supabase dashboard OR in `supabase/migrations/`.
2. Always test with different roles: citizen, staff, admin.
3. Verify that unauthorized access is blocked.
4. Document the policy logic in a comment.

## Git Workflow

- Branch naming: `feature/issue-name`, `fix/bug-name`.
- Commit messages: descriptive, lowercase, present tense.
  - ✅ `add login form with email validation`
  - ✅ `fix RLS policy for staff submissions`
  - ❌ `fix bug` or `WIP`
- Push to branch, open PR, request review.
- After hackathon, squash commits to `main`.

## Debugging Tips for AI Agents

**If a database query fails:**
- Check RLS policies: enable row-level security debugging in Supabase dashboard.
- Verify the user's role/district matches the policy condition.
- Print `auth.uid()` and `profiles.role` in the policy to debug.

**If a form doesn't submit:**
- Check console errors (browser DevTools).
- Verify the route handler exists at `/api/submissions`.
- Check auth status with `supabase.auth.getUser()`.
- Inspect Zod validation errors.

**If the PWA doesn't install:**
- Check browser console for Service Worker registration errors.
- Verify `public/manifest.json` exists and is valid.
- Ensure deployment is over HTTPS (localhost works in dev).
- Clear browser cache and reinstall.
